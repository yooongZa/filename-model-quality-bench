# 팀 평가 데이터 업로드

팀이 준비한 사진·프레임·원본 영상을 사용합니다. `videos/`의 MP4·MOV 등은 FFmpeg로 대표 프레임을 추출합니다. 기본은 10초당 1장·최대 5장이며, 5장이면 영상의 10%·30%·50%·70%·90% 시점입니다. [추출 설정과 실행](VIDEO_FRAMES.md)을 참고하세요. 평가 사진과 정답을 합성하는 기능은 없습니다. 지원 이미지 형식은 JPG·JPEG·PNG·WEBP·BMP입니다.

## 가장 쉬운 폴더 형식

```text
evaluation/
  images/
    city.jpg
    picnic.jpg
  videos/
    cycling.mp4
  answers/
    city.json
    picnic.json
    cycling.json
```

이 폴더를 `evaluation.zip`으로 압축해 Google Drive의 **내 드라이브/filename/datasets/**에 올리고, Colab 노트북의 **2. Google Drive 연결과 데이터 준비**를 실행합니다. 사진만 또는 영상만 있는 ZIP도 됩니다. 압축 해제 후 기본 상한은 2GB·10,000개 항목입니다. Colab에 올릴 수 있는 자료인지 팀에서 확인하세요.

로컬에서는 다음과 같이 가져옵니다.

```bash
python upload_dataset.py evaluation.zip --destination data/evaluation
```

명령이 출력한 데이터 경로를 실행 시 `--dataset-root "경로"`로 지정하세요. ZIP에 바깥 폴더가 있으면 실제 경로가 `data/evaluation/evaluation`일 수 있습니다. 압축을 직접 풀었다면 `images/`·`videos/` 또는 기존 `frames/`를 포함한 폴더를 지정합니다.

사진과 영상 파일명에서 확장자를 뺀 값(`city`, `cycling`)이 샘플 ID입니다. `videos/cycling.mp4`의 정답은 `answers/cycling.json`입니다. **팀은 영상 전체를 보고 정답 한 개를 작성합니다. 프레임 추출과 프레임별 파일 이름은 코드가 처리합니다.** 기존 프레임을 직접 쓰고 싶을 때만 `frames/영상ID/001.jpg` 형식을 사용하며, 이 경우 영상 폴더 이름이 ID입니다. 같은 영상을 원본과 프레임 폴더 양쪽에 중복 등록하지 마세요. ID는 전체에서 유일해야 합니다. 프레임은 파일명의 숫자 순서로 읽습니다(`1, 2, 10`). `001.jpg`처럼 시간순으로 이름을 맞추세요. 파일 수정 시각으로 촬영 순서를 추정하지 않습니다.

Colab의 기본 `VIDEO_FRAMES="all"`은 자동 추출한 프레임을 모두 한 요청에 넣습니다. 터미널에서도 `--frames all`을 지정하면 됩니다. 숫자 설정은 후보 중 그 장수만 선택합니다. 사진만 올리면 영상 조건을 건너뜁니다. 후보보다 많은 프레임을 요청하면 `unsupported`로 기록합니다. 후보를 복제해 채우지 않습니다. `frames` 비교 목록을 `[1, 3]` 등 보유 수에 맞추거나 최대 12장 이상의 후보를 준비하세요. `selection` 비교는 후보 중 6장을 고릅니다.

새 업로드는 새 폴더로 가져옵니다. 기존 폴더를 덮어쓰지 않습니다. 가져오기가 중단되거나 이미지 검증에 실패하면 남은 파일은 보존됩니다. 오류를 고친 ZIP을 새 목적지에 올리세요. 이미 성공한 데이터는 출력된 경로를 재사용하면 됩니다.

## 정답 태그는 넓게, 핵심 개념은 따로 작성

사진 또는 영상 한 건마다 `answers/샘플ID.json` 한 개를 작성합니다. 영상은 전체 내용을 보고 작성하며 프레임별 정답은 필요하지 않습니다. 아래는 **형식 설명용 가상 예시**입니다. 실제 자료에서 관찰한 내용으로 바꾸세요.

```json
{
  "keywords": [
    "자전거", "자전거 타기", "사이클링", "자전거 라이딩",
    "해안도로", "바닷가 도로", "바다", "해변", "야외", "도로"
  ],
  "core_keywords": [
    ["자전거 타기", "사이클링", "자전거 라이딩"],
    ["해안도로", "바닷가 도로"]
  ],
  "reason": "바다가 보이는 도로에서 자전거를 타고 이동합니다.",
  "place_name": null,
  "needs_review": false
}
```

| 항목 | 사람이 작성할 내용 |
|---|---|
| `keywords` | 이 자료에서 정답으로 인정할 표현 전체. **개수 제한이 없어 100개 이상도 가능**합니다. |
| `core_keywords` | 꼭 포착해야 할 개념을 묶음별로 작성합니다. 각 묶음에서 어느 표현이 나와도 한 개념을 맞힌 것으로 인정합니다. |
| `reason` | 관찰 근거. 영상의 주요 행동 변화도 짧게 적습니다. 기존처럼 1~120자 정도로 작성하면 됩니다. |
| `place_name` | 화면에서 확실히 확인되는 고유 지명. 확인할 수 없으면 `null`. |
| `needs_review` | 핵심 장면·행동을 판단하기 어려우면 `true`, 명확하면 `false`. |

`core_keywords`에는 핵심 개념 묶음을 최대 5개 넣습니다. 예시에서는 자전거 타기와 해안도로라는 **두 개념**입니다. 묶음 안의 표현 수는 제한하지 않습니다. 같은 표현을 서로 다른 묶음에 넣으면 한 태그로 여러 개념을 맞히게 되므로 코드에서 오류로 알립니다. 묶음의 첫 표현은 리포트에 표시할 대표 이름입니다. 핵심 묶음에 적은 표현도 허용 태그 목록에 자동으로 포함됩니다.

**정답 파일의 태그 수와 모델 출력 태그 수는 다릅니다.** 사람의 허용 목록은 넓게 작성하고, 모델은 기존 4필드 형식으로 태그를 최대 5개만 출력합니다. 모델에 `core_keywords`를 출력하라고 요구하지 않습니다. `answers/`는 채점에만 사용하며 모델 입력에 전달하지 않습니다.

공백·영문 대소문자·한글 조합형 차이는 정리합니다. 그 밖의 표현 차이는 허용 목록이나 핵심 묶음에 직접 적어야 합니다. 예를 들어 `사이클링`을 적어 두면 인정하지만, 등록하지 않은 동의어를 AI가 자동으로 판정하지는 않습니다. 목록에 없는 출력은 사람 확인 대상으로 표시합니다.

정답 후보가 100개여도 출력한 5개가 모두 허용되면 정밀도는 100%입니다. 핵심 재현율의 분모에는 `core_keywords`의 묶음 수만 사용합니다. 같은 개념의 동의어를 여러 번 출력해도 핵심 점수는 한 번만 올라갑니다. [계산식과 예외 처리](EVALUATION.md)를 참고하세요.

태그 수를 억지로 채우지 마세요. 실제로 보이는 대상·행동·배경과 그 표현 변형을 충분히 적고, 확인할 수 없는 지명·관계·행동은 제외합니다. `사람`, `야외`만 맞힌 응답도 정밀도는 높을 수 있으므로 핵심 개념 점수를 함께 봅니다. 최종 비교 전에 정답 목록을 확정하고 모든 모델·조건에 같은 목록을 사용하세요. 목록을 수정했다면 모든 조건을 같은 기준으로 다시 비교해야 합니다.

`core_keywords`를 생략한 기존 4필드 정답도 사용할 수 있습니다. 이때 허용 태그 정밀도만 계산하고 핵심 재현율은 빈칸입니다. 정답 파일을 생략하면 내용 채점은 비워 두고 JSON 형식·시간·오류와 사람 평가를 사용할 수 있습니다. 정답을 전부 사람이 검수했다면 선택 파일 `manifest.json`에 `{"human_reviewed": true}`를 기록하세요.

같은 영상의 프레임이 개발용과 최종 확인용에 나뉘어 들어가지 않도록 촬영 묶음 단위로 분리하세요.

## 기존 입력 목록을 유지하는 경우

`model_inputs.jsonl`이 있으면 폴더 자동 인식보다 우선합니다. 한 줄이 평가 한 건이며 모든 경로는 데이터 루트 기준입니다. 영상 프레임 순서는 배열 순서를 따릅니다.

```json
{"id":"city","media_type":"image","image_paths":["images/city.jpg"]}
{"id":"cycling","media_type":"video","video_path":"videos/cycling.mp4"}
```

기존의 `manifest.json` 프레임 시간 정보와 `reviewer/annotation_notes.json`도 선택적으로 읽습니다. 저장소는 이미지·정답·가중치를 배포하지 않습니다.
