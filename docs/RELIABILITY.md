# 재개와 검증 경계


```bash
python a_quality.py --suite resolution --resume
python -m unittest discover -s tests -v
```

완료한 응답은 형식 오류가 있어도 다시 생성하지 않습니다. 시간 초과·메모리 부족 같은 실행 실패는 다음 `--resume`에서 새 시도로 남깁니다. 기존 원문은 덮어쓰지 않습니다. 설정·입력·코드·모델 해시가 달라지면 새 `run_dir`가 필요합니다. JSONL 저장 중 프로세스가 강제 종료돼 마지막 줄이 손상된 경우에는 자동 폐기하지 않고 읽기 오류로 알립니다. 원본 로그를 복사한 뒤 손상 여부를 검토하세요.

100회 모델 재사용은 **같은 프로세스를 유지한 연속 실행**이어야 합니다. 중간에 끊긴 `soak`는 이어 붙여 100회 성공으로 처리하지 않습니다. 새 결과 폴더에서 다시 시작합니다. `.running.lock`이 남으면 해당 PID의 실행 종료를 확인한 뒤에만 제거하세요.

동시성·실패·취소·재시도 검증 범위:

| 경로 | 위험 | 구현 선택 | CPU 검증 |
|---|---|---|---|
| 정상 동시 요청 | 응답과 이미지가 뒤섞임 | 요청마다 새 messages·설정 복사, ID 연결 | 두 요청 결과 매핑 |
| 메모리 오류 | 다른 요청이 계속 실행됨 | 소유 서버 종료 후 작업 정리 | 오류 주입·종료 신호 |
| HTTP 시간 초과 | 클라이언트만 멈춤 | 소유 프로세스 종료·회수 | 가짜 HTTP 서버의 지연 응답 |
| 사용자 취소 | 모델 사용 중 객체 해제 | A는 호출 스레드에서 추론, B는 소유 서버 종료 | 취소 주입 |
| 재개 | 중복 호출·결과 덮어쓰기 | 단일 작성자·고정 작업 ID·추가 기록 | 중단 후 재개·입력 해시 변경 |
| 리포트 재생성 | 사람 평가 소실 | attempt ID로 기존 입력 보존 | 평가 코멘트 유지 |

A의 Transformers `max_time`은 생성 루프에서 확인하는 제한입니다. GPU 커널 자체가 멈춘 경우의 강제 중단을 보장하지 않습니다. 실제 CUDA·Windows·Metal의 오류 복구는 대상 장비에서 확인해야 합니다. 모델 파일을 받거나 실제 GPU 추론을 수행하지 않은 검증 결과를 장비 성능으로 해석하지 마세요.

처음 완료 조건은 **A와 B 각각 사진 1장·영상 1개에 대해 실제 응답과 리포트 확보**입니다. 이후 팀이 올린 개발용 전체 데이터에서 품질을 비교하고, 별도 촬영 묶음의 holdout(최종 확인용 데이터)으로 설정을 검증하세요.

## 업로드 경로의 검증

ZIP 업로드는 기존 폴더를 덮어쓰지 않습니다. 외부 경로·심볼릭 링크·중복 경로·암호화·크기 초과는 쓰기 전에 거부합니다. 오류나 취소 뒤에는 부분 파일을 자동 삭제하지 않습니다.

| 경로 | 동작 | 확인 방법 |
|---|---|---|
| 정상 | 새 폴더에 풀고 입력·이미지 검사 | 사진 단독·프레임 순서·바깥 폴더 ZIP 테스트 |
| 잘못된 ZIP 경로 | 쓰기 전에 거부 | `../`, 절대 경로, 심볼릭 링크 테스트 |
| 기존 목적지 | 덮어쓰기 전에 거부 | 기존 파일 보존 테스트 |
| 손상된 이미지 | 모델 로드 전에 중단, 풀린 폴더 보존 | 손상 이미지 테스트 |
| 사용자 취소 | 중단 전 파일 보존 | 쓰기 중 취소 주입 테스트 |
| 재시도 | 수정된 ZIP을 새 폴더로 가져오기 | 실패 후 새 목적지 재시도 테스트 |

이 변경은 서버의 동시 요청·종료·재개 규칙을 바꾸지 않습니다. 자동 모델 입력 목록은 메모리에서만 구성하고, 사진·정답 파일을 만들어 채우지 않습니다.
