# 결과와 평가 방법


결과는 `runs/a/<suite>/` 또는 `runs/b/<suite>/`에 저장됩니다. 모의 실행 폴더에는 `_mock`이 붙습니다.

| 파일 | 내용 |
|---|---|
| `report.html` | 조건별 결과, 오류, 원문, CSV 링크 |
| `config.json`, `backend_*.json` | 설정·환경·로드 시간·해시·서버 속성 |
| `eda.json` | 샘플 수, 사진/영상 비율, 크기, 파일 중복 |
| `references.json` | 실행 당시의 답안·검수 기준 복사본. 모델에는 전달하지 않음 |
| `requests.jsonl` | 요청별 설정·프레임·응답·형식 검사·시간 |
| `summary.csv`, `metrics.csv` | 조건별 요약·요청별 수치 |
| `review.csv` | 사람 평가 입력란과 답안·관찰 기준 |
| `telemetry.jsonl` | 그룹별 시간·메모리·활성 슬롯 표본 |
| `calibration.jsonl` | 컨텍스트 채우기 전 보정 요청 |
| `events.jsonl`, `server_*.log` | 시작 오류 및 서버 로그; 해당 이벤트가 있을 때 생성 |

정답은 팀이 업로드한 `answers/샘플ID.json`에서 읽습니다. 정답을 자동 생성하지 않습니다. 정답이 없으면 태그 점수는 빈칸이고, JSON 검사·시간·오류와 사람 평가를 사용할 수 있습니다. 모델 출력 규칙은 **v3 최대 태그 5개·4필드**입니다. 사람의 정답 `keywords`는 개수 제한이 없고, 선택 항목 `core_keywords`로 핵심 개념을 따로 지정합니다. [정답 파일 예시](DATASET.md)를 참고하세요. 사람 검수 여부는 `manifest.json`의 `human_reviewed`로 기록합니다.

자동 검사는 원문을 고치지 않고 JSON을 파싱한 뒤 필수 키·자료형·태그 개수·문자 길이·추가 키를 확인합니다. 코드 블록 제거, JSON 복구, 임의 태그 삭제를 적용하지 않습니다. `json_valid`와 `schema_valid`는 실행 오류와 별개로 기록합니다. 실패도 전체 시도의 비율 분모에 들어갑니다. 모델 로드 실패는 요청이 실행되지 않았으므로 별도 이벤트와 계획 대비 누락으로 표시합니다.

## 자동 태그 채점

채점 버전은 `allowed-tags-core-v1`입니다. 새로운 모델 호출 없이 사람이 정한 허용 표현으로 판정합니다.

| 지표 | 계산 | 저장 위치 |
|---|---|---|
| `allowed_tag_precision` | 허용된 출력 태그 수 ÷ 출력 태그 수 | `metrics.csv` |
| `core_tag_recall` | 포착한 핵심 개념 묶음 수 ÷ 전체 핵심 묶음 수 | `metrics.csv` |
| `mean_allowed_tag_precision` | 계산 가능한 요청별 정밀도의 산술평균 | `summary.csv` |
| `mean_core_tag_recall` | 계산 가능한 요청별 핵심 재현율의 산술평균 | `summary.csv` |

예를 들어 허용 목록이 100개이고 모델이 출력한 5개가 모두 목록에 있으면 정밀도는 **5/5=100%**입니다. 핵심 묶음이 3개인데 2개를 포착하면 핵심 재현율은 **2/3=66.7%**입니다. 추가 허용 태그를 늘려도 핵심 재현율의 분모는 바뀌지 않습니다. 핵심 묶음에 적은 표현은 허용 목록에도 포함합니다.

한글 조합형·공백·영문 대소문자를 정리한 뒤 등록된 표현과 비교합니다. 핵심 묶음 안의 동의어를 여러 번 출력해도 그 개념은 한 번만 셉니다. 부분 문자열이나 유사한 단어를 임의로 일치 처리하지 않습니다. `바다`가 정답이라고 `바다가 아님`을 인정하지 않습니다.

`matched_allowed_tags`, `unmatched_tags`, `matched_core_groups`, `missing_core_groups`에 판정 근거를 JSON 배열 문자열로 저장합니다. HTML에도 점수와 미등록 태그·빠진 핵심 개념을 표시합니다. 미등록 태그는 목록이 부족해서 생길 수도 있으므로 사람 확인 대상입니다. 코드가 환각이라고 확정하지 않습니다.

| 경우 | 처리 |
|---|---|
| 정상 실행·형식 통과·정답 존재 | 태그 채점 |
| 모델 출력 태그가 0개 | 정밀도는 빈칸. 핵심 묶음이 있으면 재현율 0 |
| 핵심 묶음 미작성 또는 빈 배열 | 핵심 재현율은 빈칸. 허용 태그 정밀도는 계산 |
| 정답 없음·실행 실패·출력 형식 실패 | 태그 점수는 빈칸. 형식·실행 실패율에 별도로 반영 |
| `MOCK=True` 또는 B 용량 실험 | 태그 품질 점수 계산 안 함 |

`allowed_tag_precision_n`, `core_tag_recall_n`은 각 평균에 실제로 들어간 요청 수입니다. `tag_scored_attempts`, `empty_tag_outputs`도 함께 확인하세요. 빈 값을 0으로 바꾸지 않으며, 태그 평균만으로 실패가 많은 조건을 좋게 판단하지 않도록 실행·형식 성공률도 함께 비교합니다. 요청별 평균이므로 이미지와 영상 프레임 수에 따른 가중치는 주지 않습니다. 같은 조건의 반복 측정은 각각 한 요청으로 집계합니다.

기존 `exact_tag_precision_diagnostic`, `exact_tag_recall_diagnostic` 열은 이전 결과를 읽는 용도로 유지합니다. 특히 전체 허용 목록을 분모로 삼는 기존 재현율은 주요 품질 점수로 사용하지 않습니다. 새 평가에서는 위 두 지표를 사용합니다. F1·100점 종합 점수는 만들지 않습니다.

## 사람 평가

`review.csv`의 `allowed_tag_precision_auto`, `core_tag_recall_auto`는 자동 값입니다. 미등록 표현·관찰 근거·행동 변화 등은 아래 칸에 사람이 평가합니다. 자동 값과 사람 점수를 섞지 않습니다.

`review.csv`의 사람 평가 기준:

| 필드 | 입력 기준 |
|---|---|
| `tag_precision_0to1` | 화면 근거가 있는 태그 수 ÷ 출력 태그 수. 태그가 없으면 빈칸 |
| `core_recall_0to1` | 포착한 정답 핵심 개념 수 ÷ 정답 핵심 개념 수 |
| `unsupported_claim_0or1` | 태그·근거·지명 중 관찰로 뒷받침되지 않는 주장이 있으면 1 |
| `temporal_evidence_0to2` | 영상 핵심 변화: 오류·누락 0, 일부 1, 충분히 반영 2. 사진은 빈칸 |
| `needs_review_correct_0or1` | 검토 필요 판단이 정답 기준과 맞으면 1 |
| `notes` | 판단 이유·모호한 동의어·개선할 사례 |

허용 목록에 없는 동의어와 화면 근거의 정확성은 사람이 확인합니다. 사람 입력은 리포트 재생성 시 유지됩니다. 이 예제는 사람 평가 점수를 자동 합산하거나 종합 순위를 만들지 않습니다.

```bash
python make_report.py runs/a/resolution --dataset-root data/evaluation
```

리포트를 다시 만들 때는 실행 당시 저장한 `references.json`을 사용합니다. 원본 정답 파일만 바꿔도 이미 저장된 실행의 점수가 조용히 바뀌지는 않습니다. 새로운 정답 목록으로 실험하려면 새 실행 이름을 사용하고 모든 비교 조건에 같은 목록을 적용하세요. 기존 실행에 핵심 묶음이 없었다면 재생성해도 핵심 재현율은 빈칸입니다.

Based-On: none — LMS의 분류 Precision/Recall 예제는 확인했지만 허용 태그·핵심 묶음의 서로 다른 분모를 직접 다루지 않아 project_extension으로 작성했습니다. 모델·전처리·출력 스키마는 유지합니다. 100개 허용 태그, 동의어 중복, 빈 출력, 미등록 표현, 평균 분모, 기존 정답·사람 검수 기록 보존을 회귀 검사합니다.
